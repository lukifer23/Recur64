# Recur64 V69 — T1 contract: scale + exact symmetry augmentation vs the shallow baseline

Frozen before the T1 seed is drawn. Parameters: `t1_config.json`. Authorization: the owner granted full authority to choose and run the next step (6-hour budget); this is that step.
Motivation (`RESULTS_G1_R1.md`): the 768-row-trained neural candidates memorized and did not transfer (balanced accuracy 0.50/0.53 on fresh data) while the shallow baseline did (0.764). The 768-row set is the bottleneck.
**Question:** with a fresh, ~30× larger, exactly-labelled dataset and exact label-preserving symmetry augmentation, can the unchanged one-pass model (A) or the direct-board MLP (M) generalize, and do they beat the shallow baseline (frozen D1 version and a refit on the new training data) on a sealed fresh test? Same-domain generalization only; no architecture, recurrence, hierarchy or move-selection claim.

## 0. Boundaries
E1–D3, G1 and gen-001 artifacts are preserved byte-for-byte (append-only receipts before/after; the G1 panel is a spent one-shot and is **never** used for selection — only as a secondary report-only evaluation of frozen candidates). Gen-001's sealed test stays closed. No historical V5/V6 assets (zero overlap with them is not certified).
No architecture changes, no feature augmentation of neural inputs, no hierarchy comparison, no search/self-play/policy. Precision: CUDA f32 storage/accumulation with possibly-TF32 matmul inputs (not strict FP32); baselines host f64. No CPU fallback, custom kernels, Python training, driver changes or paid compute.

## 1. Data (one fresh draw, authorized)
One new master seed from the OS CSPRNG (`t1/seed/t1_master_seed.hex`), fingerprint recorded before generation, write-once; domain-separated streams (generation, partition, selection, intervention, bootstrap, training order, augmentation). Domain, generator, teacher (≤ 5,000,000 nodes/query), canonicalization and labels are the audited V69 code unchanged (KQQvK/KQRvK/KRRvK, attacker to move, exact minimal mate depth M2/M3, nonterminal immediate children, budget n = M − 1, UNKNOWN never negative).
**Exclusion:** a new root is removed iff its canonical root key or any immediate-child key occurs in the prior index built from gen-001 AND the G1 pool (full 65-byte keys; amendment R1 semantics). **Partitioning:** connected groups (shared canonical children) among survivors; groups with > 50 roots go to train (label-blind size rule), others by keyed hash 80/10/10 into train/val/test, so no group, root or canonical child identity spans partitions.
**Quotas:** train 2,000 per family × budget × class cell (24,000), nested subsets rank < k for k ∈ {250, 1000, 2000}; val 128 per cell (1,536); test 256 per cell (3,072), sealed. Per-root cap ≤ 2 per class; deterministic keyed selection; symmetry-equivalent children deduplicated. Model rows are stored separately from root/group metadata.
**Audit before any training:** manifests; exact quotas; row/metadata; canonical identities; root–child membership; terminal exclusion; empty-cache re-analysis of all contributing roots; fresh exact re-query of every example; full-key exclusion against all prior data; partition isolation; nested-scale files; **exact label invariance under all 8 board transforms on a keyed 1,500-example sample (10,500 fresh oracle queries)**; independent-reference child checks; bounded M3 minimal-depth checks. Failure ⇒ stop; no reduced quotas, substitutions, changed seed or retry.

## 2. Training grid (pre-registered; nothing else is run)
Models unchanged: A (E1 one-pass; 1,876,417 p, canonical untrained init) and M (842→128→64→1; D1 untrained init). Recipe: batch 64 (one physical batch), AdamW (β 0.9/0.999, ε 1e-8), wd 1e-4 on weights only, global grad clip 1.0, 200-update warmup then cosine to 0.1·peak; stable BCE; fixed final update; no early stopping or best checkpoint. Example stream per run: per-epoch Fisher–Yates permutations (stream `t1_order/<run>`). **Augmentation d8:** per sample a keyed-random element of the 8-element board symmetry group applied to the attacker-relative piece grid (label-preserving: the pawnless, castling-free domain is invariant; unit-tested orbit equality with real transformed boards for both attacker colours; audited with the exact oracle).
Grid — **M:** k ∈ {250, 1000, 2000} × aug ∈ {off, d8} × peak LR ∈ {3e-4, 1e-3, 3e-3}, 30 epochs (18 runs). **A:** (k=2000,d8), (k=2000,off), (k=1000,d8), (k=250,d8) at peak LR 5e-4 with 12/12/20/40 epochs; run in that order while time remains (unfinished runs are INCOMPLETE and reported). Validation predictions at 25/50/75/100% of updates (diagnostic) and the final update (used).
**Selection rule:** per model family the completed run with the lowest final-update validation BCE (ties: higher balanced accuracy); validation only.

## 3. Final evaluation (one invocation per candidate)
Candidates, frozen by the selection rule before the test is opened: **A\*** , **M\*** , **B** (frozen D1 baseline, original standardization), **B2** (identical baseline recipe refit on the T1 train partition, host f64). Evaluated once on the **T1 test** (primary) and the **G1 panel** (secondary, report-only), each with ordinary inputs, the G1 fixed-style board derangement (label-independent, within family × budget cells; frozen before predictions) and board erasure (A/M: all squares empty; baselines: board-derived features replaced by fit means). Neural candidates additionally report 8-fold symmetry test-time-augmentation logits (report-only variant of the same invocation).
Metrics: balanced accuracy, accuracy, BCE, Brier, AUROC, confusion, per-cell, logit/confidence, fit→test gap, 5,000 paired cluster-bootstrap resamples over connected groups (same resamples for all comparisons), paired differences with 95% intervals; latency separated into startup/JIT, warmed batch and end-to-end.
**Decision rules (prospective):** *transfer:* test balanced accuracy ≥ 75%, BCE ≤ 0.55, real − derangement balanced accuracy ≥ 15 points, all integrity checks pass. *Improvement over a baseline (B and B2 separately):* gain ≥ 5 points with the paired 95% interval excluding zero and BCE no worse. Scaling/augmentation effects are described from validation metrics of all completed runs (not test); they are descriptive, not causal proofs.
