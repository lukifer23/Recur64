# Recur64 V69 — T2 contract: can a neural model clearly beat the shallow baseline?

Frozen before the T2 seed is drawn. Parameters: `t2_config.json`. Authorization: the owner approved the T2 proposal ("Approved") after `RESULTS_T1.md`.
Motivation (`RESULTS_T1.md`): with 24k fresh rows and exact D8 augmentation the direct-board MLP reached the shallow-baseline level (sealed-test balanced accuracy 0.766 vs B 0.773 / B2 0.773; tied, not better), the E1 one-pass model A stayed near chance (0.580) within a 4,500-update budget, and a report-only 8-fold symmetry average lifted M\* to 0.800 / BCE 0.428. Several T1 best configurations sat at the grid edge (largest k, highest LR).
**Question:** with a fresh 3× larger exactly-labelled dataset, (1) a symmetry-averaged *training* objective, (2) an extended scale/learning-rate range for M, and (3) a properly scaled schedule for A, does any neural candidate clearly beat the shallow baselines (frozen B and refit B2) on a fresh sealed test? Same-domain generalization only; no architecture/recurrence/hierarchy/search/policy claim.

## 0. Boundaries
E1–D3, G1 and T1 artifacts are preserved (append-only receipts before/after; the G1 panel and the T1 test are spent: never used for selection, G1 only as a report-only secondary evaluation). Gen-001's sealed test stays closed. No architecture change, no feature augmentation of neural inputs (the symmetry average is applied to the same attacker-relative piece grid), no hierarchy/search/self-play. Precision: CUDA f32 storage/accumulation with possibly-TF32 matmul inputs (not strict FP32); baselines host f64. No CPU fallback, custom kernels, Python training, drivers, paid compute.

## 1. Data (one fresh draw)
One new master seed from the OS CSPRNG (`t2/seed/t2_master_seed.hex`), fingerprint recorded before generation; domain-separated streams. Domain, generator, teacher (≤ 5,000,000 nodes/query), canonicalization and labels are the audited V69 code unchanged. **Exclusion:** a new root is removed iff its canonical root key or any immediate-child key occurs in the prior index built from gen-001, the G1 pool **and the T1 contributing pool** (full 65-byte keys). **Partitioning (T1 rules after A1/A2):** root-level keyed hash 80/10/10; selection filled test → val → train with one global taken-set keyed on the canonical child key alone, so no identical child position occurs in two partitions; reporting/bootstrap groups = connected components of contributing roots per partition.
**Quotas:** train 6,000 per family × budget × class cell (72,000), nested subsets rank < k for k ∈ {2,000, 6,000}; val 256 per cell (3,072); test 512 per cell (6,144), sealed. Per-root cap ≤ 2 per class.
**Audit before any training (unchanged from T1):** manifests, exact quotas, row/metadata, canonical identities, membership/terminal, empty-cache re-analysis of contributing roots, fresh exact re-query of every example, full-key exclusion against all prior data, partition isolation (root, group and example-child identity), nested-scale files, exact label invariance under all 8 board transforms on a keyed 1,500-example sample (10,500 oracle queries), independent-reference child checks, bounded M3 minimal-depth checks. Failure ⇒ stop; no reduced quotas, substitutions, changed seed or retry without a written amendment.

## 2. Training grid (pre-registered; nothing else is run)
Recipe unchanged from T1: batch 64, AdamW (β 0.9/0.999, ε 1e-8), wd 1e-4 on weights only, global grad clip 1.0, 200-update warmup then cosine to 0.1·peak, stable BCE, fixed final update, no early stopping or best checkpoint; per-epoch Fisher–Yates permutations (`t2_order/<run>`). Training modes: **d8** = per-sample keyed-random board symmetry (as T1); **sym** (M only) = the loss is the BCE of the *mean logit over all 8 board symmetries* of each example (no random augmentation; this model's registered inference is the same 8-view mean logit).
**M** (842→128→64→1; D1 init): k ∈ {2,000, 6,000} × mode ∈ {d8, sym} × peak LR ∈ {3e-3, 1e-2}, 30 epochs (8 runs); plus k = 6,000, LR 3e-3, 60 epochs for both modes (2 runs).
**A** (E1 one-pass, canonical init; mode d8): (k = 6,000, LR 5e-4, 18 epochs ≈ 20,250 updates), (k = 6,000, LR 1e-3, 18 epochs), (k = 2,000, LR 5e-4, 54 epochs ≈ 20,250 updates).
Validation predictions at 25/50/75/100% of updates (diagnostic); final update used. Unfinished runs are INCOMPLETE and reported. NOT in the grid: wider MLPs, other optimizers, other schedules.
**Selection (validation only):** per family the completed run with the lowest final-update validation BCE (ties: higher balanced accuracy): **A\*** (A runs), **M\*** (any M run, incl. sym), **P\*** (M runs with mode d8 only, so the effect of symmetry-averaged training is separable).

## 3. Final evaluation (one invocation per candidate)
Candidates, frozen before the test is opened: A\*, M\*, P\*, **B** (frozen D1 baseline), **B2** (identical baseline recipe refit on the T2 train partition, host f64). Each evaluated once on the **T2 test** (primary) and the **G1 panel** (secondary, report-only) with ordinary inputs (a sym-trained candidate's ordinary input = its registered 8-view mean), the board derangement (label-independent, within family × budget cells; frozen before predictions) and board erasure. Neural candidates additionally report 8-fold symmetry TTA logits (report-only).
Metrics as in T1 (balanced accuracy, accuracy, BCE, Brier, AUROC, confusion, per-cell, logits, validation→test gap, 5,000 paired cluster-bootstrap resamples over connected groups, same draws for all comparisons, latency).
**Decision rules (prospective), applied to A\*, M\*, P\*:** *transfer:* test balanced accuracy ≥ 75%, BCE ≤ 0.55, real − derangement balanced accuracy ≥ 15 points, integrity passes. *Practical improvement over a baseline (B and B2 separately):* gain ≥ 5 points, paired 95% interval excluding zero, BCE no worse. *Significant improvement (weaker, reported separately):* gain > 0 with the paired 95% interval excluding zero and BCE no worse. Effects of scale, mode and LR are described from validation metrics (not test) and are not causal proofs.

The evaluator source is verified on a validation-only fixture and frozen before the test is opened. Stop after T2; no follow-up is executed.
